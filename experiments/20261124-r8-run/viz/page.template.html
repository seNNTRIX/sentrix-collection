서비스별 로그 발생률

구간 길이 차이를 보정한 초당 로그 수. 장애의 원인 점수가 아닙니다.

데이터와 해석 범위

분포는 저장된 실험 로그를 분석한 결과입니다. 가까운 점은 비슷한 표현의 단서이며, 점이 떨어져 있다는 이유만으로 장애나 원인 서비스가 확정되지는 않습니다.

선택 로그의 거리는 384차원 원본 벡터의 코사인 거리입니다. 같은 사례에서 같은 서비스의 주입 전 로그 중 가장 가까운 표현과 비교합니다. 탐색용 비교이며 경보 임계값이 아닙니다.

네 사례 모두 마스킹 후에는 장애 뒤에 처음 보는 종류의 문장이 거의 없었고, 대신 같은 문장의 양과 오류 비율이 바뀌었습니다. Pod 장애 사례의 '주입 전'에 이미 오류가 일부 보이는 것은, 장애 시점(onset)을 Pod가 준비 해제된 첫 시각으로 정해서 주입 직후 몇 초가 '주입 전'에 들어가기 때문입니다.

사전등록 실험(R8)에서 이 로그 의미 거리를 원인 순위 모델에 더했을 때 우리 데이터 22개 사례의 순위는 좋아지지 않았습니다(차이 없음). 그래서 로그는 원인 판단의 근거를 보여 주는 용도로 씁니다.

모델·전처리·차원 축소 설정

메시지 본문과 error 필드를 추출한 뒤 식별자, 주소, Pod 이름, 시각, 숫자, 서비스 이름을 마스킹(R8 사전등록 전처리). 중복 문장은 한 번 임베딩해 재사용. 임의 좌표나 시각적 jitter를 추가하지 않음. 네 사례의 문장을 함께 펼쳐서 사례 사이 위치를 비교할 수 있음.

저장된 실제 실험 데이터(linux-v1, 반복 2) 분석 화면 · 실시간 수집·백엔드 추론과 별개 · 대시보드 재생 시연과 같은 사례

임베딩 및 시각화 아이디어: (주)케파스 제공 자료 참고. 해당 기관의 원본 데이터는 포함하지 않았습니다.
사용 도구: MiniLM, t-SNE, UMAP, Plotly.
