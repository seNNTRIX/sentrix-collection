# 졸업전시

맥북에서 [실험실](http://127.0.0.1:5190/)을 열고, 큰 모니터에서 [SentriX 개요](http://127.0.0.1:5190/display#B1-Overview)를 연다. 두 번째 주소는 제품 대시보드의 빌드 파일을 그대로 제공한다. 개요에서 자동 감지 기록을 누르면 서비스 호출 관계, 후보 순위와 근거를 조사할 수 있다.

- **실험 재현**은 수집한 데이터를 사용한다. 팀 모델의 `demo/replay-cases.json`이 제공하는 유형·위치 조합에서 선택한다. fold 2의 학습에 사용된 추천 서비스 CPU 반복 3도 시연 대상으로 고를 수 있다. 이 사례를 미학습 평가로 제시하면 안 된다.
- 관람객이 시작하면 재생 전용 Java DB에 이번 실행을 위한 새 환경을 등록한다. 운영 환경과 분리된 모델 입력 폴더에 파일을 준비하고 Java 자동 관측 주기를 30초로 설정한다. 쇼핑몰에서 기록한 특징과 누락은 그대로 유지한다. 시계만 실행 시각에 맞추고 원본 식별자와 시간차를 source.json에 기록한다. 모델은 현재 창과 10초 앞선 창을 읽는다. 장애 유형이나 주입 위치는 모델 요청에 들어가지 않는다.
- 모델이 이상을 반환하면 Java가 장애를 열고 순위와 근거를 저장한다. 정상 판정은 열린 장애를 닫는다. 보류 및 기록 끝은 정상 판정으로 취급하지 않는다.
- 큰 모니터는 시나리오 시작 전에는 운영 환경을 관측한다. 재현 시에는 같은 개요에서 관측 환경이 바뀐다. 장애 상세로 들어간 관람객은 그대로 조사할 수 있다. 개요는 실험 종료 1분 후 운영 환경으로 복귀한다. 출처는 기존 환경 선택기의 ‘재현’ 표기로 구별한다.
- 보조 선택인 **실시간 실험**은 현재 쇼핑몰 배포 구성 11개 서비스·15개 경로에서 Chaos Mesh로 180초 실험을 요청한다. 맥북의 전시 계정과 클러스터가 필요하다. k6는 사용자 트래픽을 발생시키는 도구다.

## 실행

같은 상위 폴더에 sentrix-collection, sentrix-model-server, sentrix-core, sentrix-dashboard를 두고 전시용 MySQL과 운영 관측 환경을 실행한다. JDK 21, Java JAR 및 대시보드 빌드가 필요하다. 전시 맥에서는 Finder의 **관람객 두 화면 시작.command**를 연다. 최초 설치라면 기존 replay DB 환경 1을 sentrix-core/dev/replay/rehearse.py의 환경 등록 절차로 준비한다. 재현 모델은 8001, Java는 8081, 운영 Java는 8080을 사용한다.

검증 명령은 `python3 -m unittest discover -s exhibition`이다.
